## 今日优先项目

### 1. Echo60 — 个人生物年龄追踪与模拟器

这是一个 TypeScript 实现的轻量级个人生物年龄追踪工具，定位明确、代码可读性高，非常适合做试跑教程和内容拆解。方向直接对准"我的生物年龄是多少"这个最有读者黏性的长寿话题入口。

- **证据来源：** [marswalk/Echo60 on GitHub](https://github.com/marswalk/Echo60)（2026-07-15，TypeScript，1 star）
- **可信度：** 中（新项目，代码需验证，但方向和定位清晰）
- **目标鱼塘：** 关注健康管理的普通用户、长寿内容读者、可穿戴设备用户、自媒体创作者
- **它解决什么问题：** 把"生物年龄"这个抽象概念变成可追踪、可模拟的个人数据界面，降低普通人理解衰老数据的门槛
- **试跑门槛：** 低，TypeScript 项目，`npm install` + README 即可本地跑起来
- **可做成什么：** 试跑教程 / 内容拆解 / 小红书/公众号选题素材 / 工具导航条目
- **可交付物：** README 试跑截图笔记 / "我用这个工具测了自己生物年龄"选题草稿 / 工具导航对比表
- **最低成本验证：** 今天 clone 项目 → `npm install` → 截图 → 整理 3 条功能要点
- **二次开发路径：** 加入微信/小红书数据导入适配；做成"生物年龄评估工具清单"导航页；配合可穿戴数据做拆解文章
- **售后或合规风险：** 低
- **合规边界：** 只写"这是一个自我追踪工具，不能替代医疗检测或诊断"，不宣称任何抗衰效果
- **今天最小动作：** clone → 试跑 → 截图 → 写一条小红书选题："我用 AI 工具测了自己的生物年龄，结果比实际年龄大了 5 岁"

### 2. Forever Healthy Evipedia AI Integration — 长寿干预知识库 API 化

Evipedia 是目前长寿领域最系统的干预信息百科，此次发布 AI 集成工具意味着可以通过 API 或 agent pipeline 直接调用其内容。对做长寿资讯、内容库、工具导航的人来说，这是一个现成的高质量数据源入口。

- **证据来源：** [Forever Healthy Launches Evipedia AI Integration](https://lifespan.io/forever-healthy-launches-evipedia-ai-integration/)（2026-07-15，Lifespan.io）
- **可信度：** 高（Forever Healthy 是业内有信誉的非营利机构，Evipedia 持续维护多年）
- **目标鱼塘：** 长寿内容创作者、健康管理从业者、做 AI 工具的独立开发者、科研学习者
- **它解决什么问题：** 提供结构化、持续更新的长寿干预信息，可接入 AI 工具和内容生产流程，省去自己整理文献的成本
- **试跑门槛：** 低，先读官方文档和 API 说明即可，不需要部署
- **可做成什么：** 工具导航条目 / 资料库条目 / "今天最好用的长寿信息 API"拆解文章 / 内容生产流程搭建教程
- **可交付物：** Evipedia 功能说明整理（3-5 条要点）/ 工具导航页条目 / 与其他长寿资料库的对比表
- **最低成本验证：** 今天读完官方公告 → 访问 Evipedia 网站 → 整理 3 条"它能查什么、不能查什么"要点
- **二次开发路径：** 接入自己的 AI 写作 pipeline → 自动生成"今日长寿研究摘要"栏目；做成"长寿信息源导航"的核心条目
- **售后或合规风险：** 低
- **合规边界：** 写"信息整理参考"，不写"按照 Evipedia 建议可以……"；强调信息仅供研究参考，不替代医生建议
- **今天最小动作：** 访问 [evipedia.org](https://www.evipedia.org) → 测试搜索 3 个干预词（如 rapamycin、NMN、metformin）→ 记录返回内容格式和质量 → 整理成一条工具导航草稿

### 3. 睡眠时长与阿尔茨海默相关蛋白研究 — 内容选题价值高

UT Health San Antonio 研究发现长期睡眠时间过长与血液中阿尔茨海默相关蛋白水平升高相关，角度反直觉（多睡不一定好），具有很强的大众传播价值。

- **证据来源：** [Sleeping longer may signal early Alzheimer's-related brain changes](https://www.news-medical.net/news/20260715/Sleeping-longer-may-signal-early-Alzheimers-related-brain-changes.aspx)（2026-07-15，News-Medical，学术机构来源）
- **可信度：** 中高（学术机构研究，动物或观察性研究需确认，结论需保守表达）
- **目标鱼塘：** 关注大脑健康的中老年读者、照护者、睡眠健康关注者、可穿戴设备用户
- **它解决什么问题：** 用易理解的睡眠指标（睡多久）连接大脑衰老风险，帮助读者理解"睡眠监测有什么意义"
- **试跑门槛：** 低，纯内容选题，不需要跑代码
- **可做成什么：** 小红书/公众号选题 / 睡眠与脑健康信息拆解 / 可穿戴睡眠数据解读角度
- **可交付物：** 一条选题草稿 / "睡多久是风险信号？"科普片段 / 睡眠指标与认知风险关系的简表
- **最低成本验证：** 读完原文摘要 → 记录核心数据点（睡多久算长？相关蛋白是哪个？）→ 写一条选题
- **二次开发路径：** 建立"睡眠指标 × 认知衰老"资料库栏目；配合可穿戴数据做"你的睡眠数据说明了什么"内容系列
- **售后或合规风险：** 低（只做信息整理，不做诊断建议）
- **合规边界：** 写"研究观察到相关性，不代表因果关系，不能自行诊断"；不写"睡太多会得阿尔茨海默"
- **今天最小动作：** 读原文 → 提炼 3 个反直觉数据点 → 写一条小红书选题标题备选（3 版）

- 后续升级路径：接入 API 半自动生成草稿 → 人工审核发布 → 建立付费订阅专栏

**方向三：睡眠数据 × 脑健康可穿戴数据解读模板**

## 值得观察

**1. HumanVector (jim4226/ClaudeScienceHackathon_2026)**
方向有意思——把生物年龄变成"方向状态空间"而非单一数字，结合 ECG 扰动和跨尺度证据地图。但这是黑客松作品，只有 2 stars，代码和文档完善度未知。
暂不动原因：需要先确认代码是否可运行、数据输入要求是否可得，以及 ECG 数据处理的专业门槛。等 2 周后看是否继续维护。

**2. MOJO 神经解码框架论文（arxiv 2607.14086）**
脑机接口方向的半监督学习框架，技术扎实。与 longevity 的连接是"神经接口 × 老年认知辅助"，但目前偏纯技术研究，没有直接可用的工具或数据集。
暂不动原因：试跑门槛高，需要神经电生理数据，目标鱼塘偏专业研究者，短期内难做成大众内容。

**3. 酮饮食 × 小肠癌风险小鼠研究**
反直觉角度（酮饮食的潜在癌症风险），但素材是小鼠实验，结论外推到人需要极其保守。
暂不动原因：医疗宣称风险高，容易被误读为"不能吃生酮饮食"，需要等人体研究再做内容，或只做"这项研究说了什么、没说什么"的边界拆解。

**4. EB-VAE 肿瘤建模论文（arxiv 2607.13984）**
纵向肿瘤测量 + 生存分析的联合建模框架，技术质量高，适合精准医疗数据分析方向。
暂不动原因：与 longevity 的连接较间接，目标鱼塘主要是临床研究者，不适合做大众内容，等看是否有公开数据集可以配合使用。

## 今天别碰

**1. Evo 2 基因组模型生物安全筛查（arxiv 2607.14070）**
方向是生物安全 + 宏基因组筛查，技术价值高，但与长寿/健康内容受众完全不匹配，且涉及病原体、抗微生物药物耐药性等敏感领域。做成内容合规风险极高，试跑需要专业基因组数据。今天不碰。

**2. 自行解读"睡眠时长预测阿尔茨海默风险"做成诊断工具**
今日睡眠研究是相关性观察，不是因果确认。若包装成"根据你的睡眠时间判断阿尔茨海默风险"工具，医疗宣称风险极高，可能造成不必要的焦虑或延误就医。只做内容科普，不做诊断型工具。

**3. 酮饮食干预方案建议类内容**
当前证据仅来自小鼠实验，人体临床证据不足，受众对"酮饮食"已有强烈预设立场，容易引发争议和医疗误导投诉。等有人体数据再做。
